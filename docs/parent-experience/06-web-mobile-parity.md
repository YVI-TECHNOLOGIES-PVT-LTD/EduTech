## 1. Executive Summary

This audit compares feature parity, screen capabilities, and data synchronization between the **Parent Web Dashboard** ([apps/web_app](file:///Users/sathish/Documents/GitHub/EduTech/apps/web_app)) and the **Parent Mobile App** ([apps/mobile_app](file:///Users/sathish/Documents/GitHub/EduTech/apps/mobile_app)).

### Primary Parity Assessment:

- **Pre-Admission Workflows:** **High Parity**. Both platforms provide comprehensive application listing, step milestone progress tracking, document uploads, and pre-admission fee checkout.
- **Enrolled Financial Overview:** **Moderate Parity**. Both platforms consume the canonical endpoint `GET /v1/fees/my` and display multi-child financial metrics. However, Web provides an itemized installment schedule and component list, while Mobile displays only summary metrics and the next upcoming due.
- **Enrolled Payment Checkout:** **Missing on Both**. Neither platform has wired online Razorpay checkout for enrolled student academic term dues.
- **Notifications:** **Mobile-Only Advantage**. Mobile includes an in-app notification center with an unread badge counter, while Web has no parent-facing notification center.

## 4. Key Takeaways for Web/Mobile Alignment

1. **Parity Target 1 (Installment Schedule):** Build a dedicated mobile screen `app/(parent)/fees/[studentId].tsx` replicating the itemized installment table from `MyFees.tsx`.
2. **Parity Target 2 (Enrolled Fee Checkout):** Implement online checkout modal on both Web and Mobile for paying scheduled installment dues.
3. **Parity Target 3 (Web Notification Bell):** Add an in-app notification bell with unread badge counter to the Web parent layout.
4. **Parity Target 4 (Parent Receipt Access):** Expose parent-authorized receipt endpoints and render digital receipt views on both platforms.
