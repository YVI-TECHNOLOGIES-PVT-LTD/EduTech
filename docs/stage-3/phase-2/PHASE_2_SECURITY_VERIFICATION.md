## 2. Preserved External Database Security Change Requests (Frozen DB Scope)

The following database-layer security items documented in Phase 1 Gate B remain **intentionally untouched** under the Phase 2 Database Freeze and must be applied via an authorized DBA maintenance window prior to executing Stage 3 Assessment/Rubric/AI stored procedures:

1. **Missing RLS Policy on `assessment_rubrics`:** `assessment_rubrics` has RLS enabled (`rls_enabled = true`) with `0` policies (alongside `108` Stage 1/2/Timetable tables requiring policy review if non-`bypassrls` DB roles are introduced).
2. **Invalid Status Literal in `p_assessment_attachments_select`:** References `'results_reviewed'`, disallowed by `assessments_status_check`.
3. **Case-Sensitive Role Checks in Stored Procedures:** `auth_is_academic_admin`, `s35_apply_result_correction_approval`, and `s36_evaluate_assessment_mcq` check lowercase role literals (`'admin'`, `'principal'`, etc.) against capitalized `roles.role_name` values (`'Administrator'`, `'Principal'`, `'Super Admin'`).
4. **Missing ANN Vector Index on `document_chunks`:** Documented for DBA tuning before high-volume RAG embeddings.
5. **Unlinked Historical Student Accounts:** `527 / 733` (`71.9%`) student records have `user_id = NULL` (`525` in Greenwood School, `2` in NPS Ahmedabad). Protected via read-only audit, dry-run inspection, and conflict-guarded `POST /api/v1/students/:id/link-user` without unauthorized bulk credential generation.
