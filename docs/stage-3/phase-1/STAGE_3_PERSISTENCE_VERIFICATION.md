## 2. Critical Forensic Audit of `apps/backend/src/lib/prismaClient.ts`

### 2.1 How `PrismaClient` Is Instantiated and Proxied

1. **Singleton Creation (`L412–418`)**: `rawPrisma = globalThis.__prisma ?? new PrismaClient({ log: ['warn', 'error'] })`, wrapped once via `wrapWithFallbackProxy(rawPrisma)`.
2. **Stale `@prisma/client` DMMF Discovery**:
   - Inspecting `apps/backend/node_modules/@prisma/client` (`Prisma.dmmf.datamodel`) reveals only **109 models** and **78 enums** compiled into the generated client!
   - Meanwhile `apps/backend/prisma/schema.prisma` contains **148 models** and **92 enums** (pre-existing unstaged schema expansion visible in `git status`/`git diff`).
   - **Result**: All **39 Stage 3 models** (`ai_copilot_*`, `assessment_*`, `assessments`, `classroom_*`, `competency_analytics_thresholds`, `intervention_*`, `learning_activit*`, `learning_gap_thresholds`, `student_competency_analytics`, `student_learning_gaps`, `student_progress_card*`) **DO NOT EXIST on `rawPrisma`** (`prop in obj` is `false` at `prismaClient.ts:293`).
3. **Silent In-Memory `Map` Redirection Hazard (`L123–282, L389–404`)**:
   - When any code accesses `prisma.<unmappedModel>` (e.g., `prisma.classroom_sessions.create(...)` before `prisma generate`), the `Proxy` enters `L389–404`.
   - If the model name is in `FINANCIAL_PERSISTENCE_MODELS` (`L26–72`, which contains 46 financial + Stage 2 academic models), `createStrictFinancialDelegate()` **throws** `[Persistence Error]` on any write (`L74–120`).
   - **CRITICAL DANGER FOR STAGE 3**: **None of the 39 Stage 3 tables are listed in `FINANCIAL_PERSISTENCE_MODELS`!** Therefore, ANY delegate call like `prisma.assessments.create(...)`, `prisma.learning_activities.findMany(...)`, or `prisma.classroom_sessions.update(...)` **silently hits `createSafeModelDelegate()` (`L183–282`) and reads/writes to the RAM `fallbackStores` `Map` (`L123`) WITHOUT throwing an error and WITHOUT touching PostgreSQL!**
4. **Trap Even _After_ `prisma generate` (`L342–362`)**:
   - Even when `prop in obj && obj[prop] !== undefined` (real generated delegates!), `wrapWithFallbackProxy` wraps real delegates in a secondary `Proxy` (`L342`) that checks `FINANCIAL_PERSISTENCE_MODELS.has(prop)` (`L345`) and **throws** on `create`/`createMany`/`update`/`updateMany`/`delete`/`deleteMany`/`upsert`!
   - **Observed Active Bug Proof**: `apps/backend/src/modules/fees/fees.routes.ts:2588` executes `prisma.student_charges.updateMany(...)` inside `prisma.$transaction([...])`, while `student_charges` is listed at `prismaClient.ts:31` inside `FINANCIAL_PERSISTENCE_MODELS` — guaranteeing that code path throws `[Persistence Error]` if invoked! Similarly, Stage 2 academic tables (`learning_resources`, `curriculum_plans`, `timetable_entries`, `lesson_plans`, etc.) are listed in `FINANCIAL_PERSISTENCE_MODELS`, forcing all Stage 2 repositories to bypass Prisma delegates entirely.
5. **Raw SQL & Transaction Behavior (`L294–334`)**:
   - `$queryRaw`, `$queryRawUnsafe`, `$executeRaw`, `$executeRawUnsafe` bypass delegate interception, talk directly to PostgreSQL, propagate DB errors, and include single retry on `ConnectionReset`/`10054` (`L316–334`).
   - `$transaction(fn)` wraps `tx` in `wrapWithFallbackProxy(tx)` (`L301`), meaning `$queryRaw`/`$executeRaw` inside `$transaction` hit PG transactionally, whereas any unmapped `tx.<s3Model>` would silently write to RAM!
6. **Raw SQL Transaction Gap in Existing Stage 2 Repositories**:
   - Static scan across `apps/backend/src` found `$queryRaw`/`$executeRaw` in `42` files and `$transaction` in `22` files.
   - However, several Stage 2 multi-step repositories (verified in `curriculum.repository.ts` and `learning-resource.repository.ts`, both `$transaction: false`) execute sequential raw SQL queries **without** wrapping them in `prisma.$transaction(...)`, risking partial state if an error occurs mid-operation.

## 4. Mandatory Remediation Directives for Phase 2 Entry

Before ANY Stage 3 business logic is written or executed:

1. **Run `npx prisma generate`** in `apps/backend` (as authorized in Phase 2 once implementation begins — **strictly prohibited during Phase 1**) to regenerate `@prisma/client` from `109 → 148` models and `78 → 92` enums, **OR** enforce strict raw-SQL repositories for S3 while blocking all unmapped delegates.
2. **Eliminate Silent RAM Fallback in `prismaClient.ts`**: Remove `createSafeModelDelegate` + `fallbackStores` completely so any unmapped delegate call **throws loudly** (fail-fast) rather than silently saving production records to RAM.
3. **Fix `FINANCIAL_PERSISTENCE_MODELS` Interception Conflict**: If ORM delegates (`tx.<model>.create`) are desired in Phase 2, remove the write-blocker on already-mapped Prisma delegates (`L344–362`), or clearly document that `FINANCIAL_PERSISTENCE_MODELS` only guards non-DMMF access.
4. **Enforce `$transaction` Boundaries**: Every Stage 3 write involving multi-table operations, PG stored procedures, or check-then-act state transitions MUST execute inside `prisma.$transaction(async (tx) => ...)`.
