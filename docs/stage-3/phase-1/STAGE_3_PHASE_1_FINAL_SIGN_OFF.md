## 3. Non-Negotiable Phase 2 Entry Gates (Pre-Conditions)

Phase 2 feature implementation **MUST NOT begin** until these verified Phase 1 defects are resolved cleanly:

### Gate A — Technical, Runtime & Codebase Fixes (Permitted under Phase 2 Entry)

1. **Sync Prisma Client & Retire Silent RAM Fallback (`prismaClient.ts`):** Run `prisma generate` to align `@prisma/client` DMMF from `109` models / `78` enums to all `148` models / `92` enums. Remove/disable `fallbackStores` Map interception (`L389–404`) and audit `FINANCIAL_PERSISTENCE_MODELS` (`L26–120`, `L344–362`) so every persistence error fails fast rather than writing silently to memory.
2. **Plug Public RBAC Leak (`routes.ts` `L590–615`):** Remove unauthenticated `/public/inspect-rbac`.
3. **Enforce Tenant Boundary Middleware (`routes.ts`, `tenant.middleware.ts`):** Mount `resolveTenantMiddleware` across `/v1/academic`, `/v1/students`, `/v1/parents`, `/v1/parent`, and all new Stage 3 routes; disable silent fallback to `DEFAULT_ORG_ID` / first active DB org on multi-tenant API calls.
4. **Harden Session Context & Repair Startup RBAC Sync (`session.service.ts`, `server.ts`, `env.ts`):** Resolve verified `staffId` / `studentId` / `parentStudentIds` on `req.user`; enforce non-default JWT secrets in non-dev environments; fix or replace `runRBACSelfHealing()` (`L120–169`, which targets non-existent Supabase RBAC tables instead of `roles(role_id, role_name)`).
5. **Provision Student Accounts (`students.user_id`):** Address the live data gap where **`527` of `733` (`71.9%`)** enrolled students have `user_id = NULL` and cannot sign in to `StudentDashboard` or Stage 3 portals.
6. **Repair Test Runner & Mobile Typecheck Gates:**
   - Replace dummy `pnpm --filter @edutrack/api test` script with a real TypeScript test runner hitting PostgreSQL (never RAM mocks).
   - Fix the `4` TS errors in `apps/mobile_app` (`src/api/endpoints.ts:106` TS1117 duplicate `HELPDESK`; `src/api/helpdesk.api.ts:59,79,92` TS2339 missing `BY_ID`/`REPLIES`).
   - Close open Vite handle (`vite.close()`) in `apps/web_app/scripts/run-navigation-tests.mjs` so navigation checks exit cleanly with code `0`.

### Gate B — Explicit Database Maintenance / Change-Request Items (Blocked Until Explicitly Authorized Outside Freeze)

Because `schema.prisma` and PostgreSQL DDL are frozen under Stage-1/Phase-1 rules, these three DB-level defects require explicit DBA/product change approval before full Admin/Rubric execution in PG:

1. **PG Case-Sensitive Role Name Bug (HIGH):** `public.auth_is_academic_admin`, `public.s35_apply_result_correction_approval`, and `public.s36_evaluate_assessment_mcq` check `ro.role_name IN ('admin', 'principal', 'coordinator', 'academic_coordinator')`, whereas live `public.roles` stores `'Administrator'`, `'Principal'`, `'Super Admin'`. Requires case-normalized matching or explicit DB fix before Admins/Principals can execute `s35`/`s36` PG stored procedures cleanly.
2. **Missing RLS Policies on `assessment_rubrics` (HIGH):** `assessment_rubrics` has `rls_enabled = true` and `0` policies (also `108` Stage 1/2/Timetable tables have `rls_enabled = true` with `0` policies). While `postgres` has `rolbypassrls: true`, non-bypass RLS roles cannot access rubrics without policies.
3. **Invalid Status Literal in `p_assessment_attachments_select` (MEDIUM):** References nonexistent status `'results_reviewed'` prohibited by `assessments_status_check`.

## 4. Recommended Phase 2 Sequencing

1. **Wave 0 — Pre-Conditions & Vertical Slice Proof:** Apply Gate A fixes (`prisma generate`, `prismaClient.ts` cleanup, `/public/inspect-rbac` removal, `resolveTenantMiddleware` wiring, test harness activation, mobile TS fix, Vite script close fix), plus confirm DBA resolution path for Gate B (`s35`/`s36` PG role check & `assessment_rubrics` RLS).
2. **Wave 1 — Classroom & Learning Activities (`S3.1` & `S3.2`):** Deliver timetable-to-session generation (`s31_*`), teacher live session controls & hybrid attendance, `'homework'` due-date tracking, `'project'` multi-file submissions (`5` x `10MB` via `upload.middleware.ts` + `StorageService`) & immutable reviews, plus WebSocket notifications.
3. **Wave 2 — Assessments, Question Bank & MCQ Evaluation (`S3.5` & `S3.6` MCQ-Only):** Deliver MCQ question bank, `student_assessment_question_options` secure exam delivery, deterministic `s36_evaluate_assessment_mcq()` execution, component/rubric entry, competency mapping, and `assessment_result_approvals` flow (`s35_*`).
4. **Wave 3 — AI Teacher Copilot (`S3.4`):** Deliver PG-backed queued generation (`'en'`, published `curriculum_plans`) using `AiProviderFactory` + `LessonPromptBuilder.sanitizeInput()` + org-filtered RAG context, transactional approval into immutable `ai_copilot_material_versions`, and AI intervention recommendations.
5. **Wave 4 — Gaps, Competency Analytics & Holistic Progress Cards (`S3.7`, `S3.8`, `S3.9`):** Deliver automatic/teacher gap confirmation -> 1:1 interventions -> append-only `is_parent_visible` notes, `'concept_mastery'` & `'bloom_level'` dashboards in `queries/`, and staff-contributed progress card compilation + signed `puppeteer` archival PDFs.
6. **Wave 5 — Live Portals & Mobile Parity:** Replace `StudentDashboard.tsx` mocks (`87`, `12500`, `3`, `2`, dead `/app/student/*` links) with live RTK Query widgets, complete Parent Portal visibility flows (`ParentPortalPolicy` + `AutoTranslator`), and hydrate `@edutrack/mobile` `(teacher)`/`(student)` placeholder screens.

## 6. Formal Sign-Off Decision

**Decision:** **`READY FOR PHASE 2 WITH DOCUMENTED BLOCKERS`**

The PostgreSQL database contract is physically present and behaviorally rich for **6 of 9** core Stage 3 areas (`S3.1`, `S3.2` project workflow, `S3.4`, `S3.5` single-correct MCQ/rubrics, `S3.7`, `S3.8`, plus staff-authored `S3.9`), while **S3.3 (Adaptive Learning Engine)** and **AI/subjective S3.6 (AI Evaluation Engine)** are **HARD DATABASE BLOCKERS** that must remain cleanly excluded from Phase 2 implementation until post-Stage-3 schema changes are approved. Proceeding to Phase 2 after clearing **Gate A** guarantees strictly authentic, PostgreSQL-backed, multi-tenant Stage 3 delivery.
