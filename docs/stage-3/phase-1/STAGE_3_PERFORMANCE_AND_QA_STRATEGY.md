## 2. Database & Runtime Performance Hotspots

### 2.1 PostgreSQL Indexing & Trigger Overheads

1. **Verified Good Scheduling Protection:** Stage 2/Timetable tables already enforce GIST exclusion constraints (`ex_academic_terms_no_overlap`, `ex_bell_schedule_periods_no_overlap`, `ex_staff_unavailable_slots_no_overlap`) and partial unique indexes (`uq_timetable_one_published_per_year`, `uq_classroom_sessions_timetable_date`).
2. **Vector Similarity Scan (`public.document_chunks`):**
   - Contains `38` live rows (`3072`-dim Gemini embeddings) indexed ONLY by `document_chunks_pkey`, `uq_document_chunks_org_doc_index`, and `ix_document_chunks_org` — **no `hnsw` or `ivfflat` ANN index**.
   - **Mitigation:** Always restrict `$queryRaw` cosine similarity queries by indexed `org_id` + narrow document filters, enforce short PG statement timeouts, and cap retrieved chunks (`TOP_K`).
3. **High-Cardinality Batch Stored Procedures:**
   - `s31_generate_classroom_sessions_for_date_range`: Iterates `timetable_entries` (`1,440` live rows across schedules) across date windows. Running multi-month generation synchronously inside an HTTP call risks gateway timeouts (`> 25s`). **Design Rule:** Enforce bounded date ranges per call (e.g., term/month chunks) or trigger generation asynchronously via PG-tracked job status with chunked transactions.
   - `s36_evaluate_assessment_mcq`: Acquires row locks across `assessment_student_answers` and writes `assessment_results` + triggers competency recalculation. For large cohorts (e.g., full grade/school), run asynchronously after transitioning `assessments.status` -> `'closed'` or batch cleanly inside short transactions.
4. **On-Demand Analytics Aggregation (S3.8):**
   - Since school/grade/section rollup tables do not exist (`student_competency_analytics` is student-scoped), institutional dashboards aggregate `student_competency_analytics` joined with `student_enrollments`. **Rule:** Apply tenant-scoped read caching (`CacheAdapter`) with explicit invalidation on `assessments` result publication and corrections (`s35_apply_result_correction_approval`).

### 2.2 Single-Node In-Memory State Bottlenecks (`CacheAdapter`, `QueueAdapter`, `SessionService`)

- `apps/backend/src/cache/cache.adapter.ts`, `jobs/queue.adapter.ts`, and `auth/session.service.ts` (`sessionCache` Map, 5-min TTL) operate exclusively inside Node heap memory:
  - **Cache Drift:** Multi-worker/multi-replica deployments will serve stale competency analytics or revoked user permissions up to TTL expiration.
  - **Queue Loss:** Container restarts drop pending `report-queue` / `export-queue` / AI jobs.
  - **Mitigation:** Anchor durable Stage 3 state transitions inside PostgreSQL columns (`ai_copilot_generation_requests.request_status`, `student_progress_cards.workflow_status`, `assessments.status`) and keep read caches strictly short-TTL and safely recoverable from PG.

### 2.3 LLM Latency & File Bandwidth Protection

- `GoogleGenAiProvider` enforces a `25s` timeout (`ai-provider.client.ts`); `RagRetrievalService` enforces `10s`. AI Copilot endpoints MUST return `202 Accepted` immediately after persisting `'queued'` status in `ai_copilot_generation_requests`, delivering completion updates asynchronously via WebSockets (`RealtimeNotificationServer`) or lightweight polling.
- Project file uploads (`upload.middleware.ts`) cap requests at `<= 5` files x `10MB` = `50MB` max memory buffering (`multer` buffer inspection). Enforce rate limits per user/IP (`app.ts`) on upload and AI generation routes to avoid heap OOM under concurrent bursts.
