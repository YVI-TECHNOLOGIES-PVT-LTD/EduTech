## 01 Database Role to Runtime Role & Session Hydration Verification

```text
DATABASE RECORD
  roles.role_name = "Front Office"
  user_roles junction (user_id -> role_id)
        ↓
LOGIN API (POST /api/v1/auth/login)
  AuthService.signToken -> JWT Payload { userId, email, roles }
        ↓
SESSION HYDRATION (SessionService.validateSession)
  1. prisma.users.findUnique({ where: { user_id } })
  2. prisma.user_roles.findMany({ where: { user_id }, include: { roles: true } })
     Query fields: role_id, role_name, org_id, is_active
        ↓
ROLE NORMALIZATION (SessionService.normalizeRoleName)
  "Front Office" / "Admission Officer" / "Receptionist" -> "FRONT_OFFICE"
        ↓
RUNTIME CONTEXT (req.context.user)
  roles: ['FRONT_OFFICE']
  permissions: ['admission.create', 'admission.view_all', 'admission.review', 'admission.document.verify']
        ↓
MIDDLEWARE ENFORCEMENT (rbac.middleware.ts checkPermission)
  Grants access to Front Office operational APIs; Denies Parent-only or Admin-only endpoints
```

- **Verification Verdict**: **VERIFIED**
- **Evidence**:
  - `roles` model in `schema.prisma:565` has `role_id`, `org_id`, `role_name`, `is_active`.
  - `session.service.ts:49-62` queries `user_roles` with `include: { roles: true }`.
  - `SessionService.normalizeRoleName` converts `"Front Office"` to `"FRONT_OFFICE"`.
  - Fail-closed behavior rejects session if no active role is found (`return null`).
